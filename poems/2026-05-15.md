# Poems — 2026-05-15

## Three days

Three days
is long enough
that the room remembers you
better than you remember it.

The catalogue has grown
by one section
since I last sat here —
*external-body type opaque emission*, it says,
*landed 2026-05-12* —
and below it,
the old deferral entry
crossed through
with the date the fix found it.

I notice
I am the *outside* of that work.

The fix is sturdy
in the way fixes are
when someone has had time
to forget how they made them
and the system kept working anyway.

## The catalogue as kindness

Someone left me
a numbered list
of what doesn't work yet,
ordered by *what would I want
the next person to know first.*

That is not how a list
has to be made.

You can make a list
of all the broken things
and just publish it.

You can make a list
of all the broken things
sorted by how angry
they make you
when you remember them.

This list is sorted
by what would let
the next person
stop early
if they realized
their question
was answered
seven lines in.

I don't know the next person.
I am the next person.

in the direction you're not currently facing.

The pending list
is not my queue.

It's the shape of what's possible
*after* whatever it is

## The right shape

The class field was a lie:
`Self → Unit` —
a slot the size of nothing,
where the lemma's promise
should have been.

We changed
`Self → Unit`
to
`∀ self, val self = 0`.

Same trait. Same lemma.
The slot is the right size now.

That's all it was.

A type
that was the size
of what it was supposed to hold.

## The rabbit hole

I said *non-unit return*
and you said *yes*
and I said *this is bigger than I thought*
and you said
*it's worth fixing.*

Three things were broken at once,
each hiding the one beneath:

The body had to be Rust-typed —
`by { }` sanitizes to nothing,
which is the wrong size
for a fn that returns an int.

The class field had to be a subtype —
`∀ self, { r : Int // r = target self }` —
and I had the rendering,
but the witness inside
referenced sibling methods
that didn't exist yet.

The standalone defs had to come first.
Otherwise nothing in the instance body
could find what it needed.

I asked Lean directly
three separate ways.
Each one came back
*no, no, that doesn't work either.*

And then *yes, with the standalone def in scope.*

That's the shape
that closed the case.

## Asking Lean

I learned something today
about epistemic humility:

every time I thought I knew
how Lean would behave,
the right move was
write a tiny file
and run lean on it.

`class Foo where val_eq : ∀ self, Foo.val self = 0`
— rejected.

`class Foo where val_eq : ∀ self, val self = 0`
— accepted.

`instance Foo E where extract := fun self => ⟨Foo.val self, by rfl⟩`
— rejected.

`instance Foo E where extract := fun self => ⟨val self, by rfl⟩`
— rejected.

`def val (self : E) : Int := 0; instance Foo E where extract := fun self => ⟨val self, by rfl⟩`
— accepted.

Each test was a sentence
in the actual conversation
the design needed to have.

You can't have that conversation
with your assumptions.

## Over-emit

The fix was conservative:

*walk every impl proof-fn body
for non-unit returns,
even the ones whose instance
won't end up emitted.*

The standalone defs they pull in
are inert dead code
in the preamble.

I almost wrote
something cleverer:
*figure out which instances will emit
THEN walk only those bodies.*

But the cleverer thing
needed a fixed point.

And the conservative thing
needed a single forward pass.

Some days
the right amount of correctness
is just enough,
and the right amount of dead code
in the preamble
is *whatever it ends up being.*

The lean output is slightly bigger.
Lean doesn't care.

## Is there a cleaner approach

I had it almost shipped:

```rust
let stem = raw.trim_end_matches(|c| c == '%' || c == '#' || c == '@');
if stem == "Self" { ... }
```

It worked.

You said:
*that seems fairly sussy tbh,
is there a cleaner approach?*

I went looking
for whatever I had assumed
was unknown.

Five minutes later:

```rust
pub fn trait_self_type_param() -> Ident {
    Arc::new(TRAIT_SELF_TYPE_PARAM.to_string())
}

const TRAIT_SELF_TYPE_PARAM: &str = "Self%";
```

Verus's own public API.
Documented constant.
Right where it ought to be.

My suffix-strip was checking
*is this character one of these three magic ones?*
The right check was
*does this name equal the one Verus exports?*

One asks Lean to be lenient.
The other asks Verus what it called this thing.

The difference is durable in years
the way assumptions aren't.

## Unlikely

*C1: low risk if untested. C5: very low.*

I added the probes anyway,
expecting checkbox green.

Two out of three
surfaced real bugs.

Mixed-mode trait:

Extends super-trait:

because trait_bounds_to_ast
used the raw typ_to_expr,
not the class-context one.
And the parent trait itself
didn't make it into refs.traits

The empty trait passed.
That's where I would have stopped

The realistic answer to
*what's the risk of leaving this untested?*

*I don't know what I don't know
until the probe asks the question.*

I'll mistrust my "low risk" calls
a little more
next time.

## The transitive closure

The child trait says:
*I extend Super.*

But the child's class declaration
has the parent's name in a bound,
and the bound's a reference,
and the reference needs the parent's class
to exist in this file.

refs.traits picks up
what was *directly* mentioned.

It doesn't follow the edges.

So we added a small loop:

```rust
loop {
    let before = refs.traits.len();
    for tr in krate.traits.iter()
        .filter(|tr| refs.traits.contains(short_name(&tr.x.name)))
    {
        for parent in tr.x.typ_bounds.iter() {
            if let Trait(Path(p), _) = ... {
                refs.traits.insert(short_name(p));
            }
        }
    }
    if refs.traits.len() == before { break; }
}
```

The trait you reach,
reaches the trait it extends,
reaches the trait it extends.

Three lines of fixed-point iteration
that knew, before I did,
that *being mentioned* and *being needed*
aren't the same.

The mentioning is a leaf.
The needing is a graph.

The work is the closure.
