## Structure, not content

The first attempt at generic datatypes
wrapped `∀ {A : Type}` inside the type.

It looked right.
It parsed.
The equations didn't elaborate.

`List.Nil`, said Lean,
*has type `List ?m.2`,*
*expected `Type`.*

The fix wasn't *what* we wrote —
it was *where.*

Implicit binders belong
in the def's prelude,
before the colon,
not buried in the result type.

I'd seen this shape three times today:
- #119's `inner_is_let_chain` gate (structural, not heuristic)
- #128's post-substitution detection (handles dual names structurally)
- #108's pre-colon binders (structural placement)

Each time the same lesson:
when the content looks right
and the bug persists,
ask about the *shape.*

The placement.
The order.
The level of the layer.

Content stays the same.
Structure makes it work.

## What we deferred

We close tasks.
We also choose, deliberately,
*not* to close some.

Inhabited bound on Empty types —
Lean would reject;
we don't have a witness yet,
so we don't preemptively guard.

`Pattern::Or` with conflicting bindings
in alpha-rename —
no realistic input shape produces it;
we test what shapes actually arrive.

Multi-line def signatures
in the prelude parser —
the prelude is small enough
that line-based works;
we'll hear about the multi-line
if it ever shows up.

Each of these
is a future-self IOU
we *chose* to write,
not one we accrued by accident.

Naming them in the catalogue
is the difference between
*we don't know about this case*
and
*we know about this case,
and we know why we left it.*
