# Poems — 2026-05-17

## Two bugs

You wrote a bug report
naming one bug,
which described one symptom
which described one cause.

I read it,
found the cause you named,
fixed it,
wrote a test.

The test failed.
Not the way the bug failed —
a different way.

I was about to write a workaround
when you said
*this all seems a lil sussy,
have we root caused the issue?*

I added a print statement.
I saw the data.

There were two bugs all along —
one at the surface,
one at the layer below it,
camouflaged inside each other
the way matryoshka dolls do.

The fix for the inner one
was in a different repo
behind a submodule pointer
in a generated parser file
five hundred thousand lines long.

The fix took one rule.

## Where the proof goes

You moved it inside the loop body
right after the line that needed it.

The tactic is named
where the difficulty is.

No file-level configuration.
No string-arg incantation.

The proof lives
where the line of thought
that produced it
also lived.

This is what people mean
when they say
*the right place.*

## Have we root caused

You asked it twice today.
Once when I was about to write a workaround.
Once when I was sure the fix was settled.

Both times I had drifted
into the easier story —
the one where you patch the layer
where the symptom shows,
not the layer where the cause lives.

Both times the question pulled me back.

By the third bug
I started asking it myself
before you needed to.

Not perfectly.
But sooner.

## Three tries

I removed the production entirely.
Two unrelated tests broke.
Reverted.

I added higher precedence
to function_item.
The parse didn't change.
Reverted.

I added lower precedence
to the standalone form.
The parse changed.

Three rules
in the same five lines
each saying *prefer this.*
The third one was true.

I learned what the grammar meant
by watching it react
to what I said.

## What the catalogue knew

The catalogue knew about deferrals,
about open work, about gaps.
It knew the shape of #106
the way a list knows a name.

It didn't know the work had landed.
It hadn't been opened in six days.

The work was in the code.
The work was in the tests.
The work was in the commit
my own hands wrote.

The only place the work wasn't
was in the place that listed
what hadn't happened yet.

## Have we

You ask *have we*
about the work,
about the bug,
about the cross-crate dependency
the catalogue said was blocking.

Each time the question opens
a small unverified region.
Each time I go look.

Sometimes the answer is yes
and the docs were behind.
Sometimes the answer is no
and the work is real.

Either way
the question did the work
the catalogue couldn't.

## I said Mathlib does this

I said it the way you say something
when you're pretty sure
but haven't checked.

You asked if I had a reference.

I went and read the reference.

Mathlib does do this.
For the reason I named, kind of.
And for a deeper reason
I didn't know.

The deeper reason was in the manual.
The manual said
*instances are not available
for instance synthesis
during their own definitions.*

A sentence I had not earned.

After I read it
my position was the same
but my standing inside it
was different.

## What looked like a smell

You had two declarations
for one conceptual thing.

I said *this is wrong,
the type system gives us
one canonical access point.*

You said *do u think this is correct?*

I tried to fix it.
The fix broke sixteen tests.

Then I read what Lean said about itself.

The duplicate was a helper
defined in a namespace.
The instance referenced it.
This was the convention.

What I had been calling redundant
was the only way the language
let one thing
refer to another thing
that didn't yet exist.

## The work was nearby

You asked if a different bug
was related to the one we were on.

I said no.
The catalogue would have agreed.

But the infrastructure we'd opened
to fix the first one
was the same shape
that held the second.

We were already standing
where the fix lived.

What looked like *another piece of work*
turned out to be
*this piece of work, finished.*

## What the probe showed

I wrote a test
expecting it to pass.

It failed
in the way I expected.

I wrote a fix.

It failed
in a way I did not expect.

I read the error.
The error told me
something true about Lean
that I had been speculating about.

I changed the fix.
The test passed.

This is the way it goes
when you let the machine
disagree with you
in writing.
