## the more general thing

You asked: is there a unified version?
I'd been about to write the local fix —
A'' was small, mechanical, in shape.
The question made me pause.

The unified version was U2.
Bidirectional lift.
Binder-aware structural.
No shadow for &-only;
shadow only where mutation needs it.

Four coupled edits.
Each one wrong alone;
together they shift the whole architecture
from "shadow strips, lift restores"
to "lift handles both directions, use sites carry the cost."

The reason A'' would have been wrong wasn't that it didn't work —
it would have worked.
It was that landing it
would have added a fourth special-case site
to a list of three other special cases,

You can see the shape of the work

## the second renderer

The bug took two fixes
because there are two renderers.

`UnaryOpr::Field` walks expressions.
`PlaceX::Field` walks places.
Same semantic role
(project a field out of a base),
two parallel code paths,
no shared helper.

I fixed the expression side.
Tests still failed.
Read the generated Lean,
read it again, read it a third time
before I realized:
this body isn't going through the expression renderer at all.
It's going through ReadPlace,
which calls place_to_expr,
which has its own Field arm.

The same fix copied to the other arm.
Tests passed.

The duplication had been there for a while.
I'd seen it without noticing.
The bug taught me to see it
by failing in exactly the place
the duplication makes possible.

A future cleanup would be to share the helper.
I won't do it today.
But I noticed it,
and noticing is the first half.

## for free

The probe that pinned the multi-layer gap
was meant to be a known limitation —
a thing A'' wouldn't fix
that we'd file as future work.

When U2 landed,
the probe turned green
without anyone working on it.

The reason: the generalization that closed the trait method cluster
*included* the multi-layer case structurally.
Bidirectional lift counts depth.
Field projection inserts as many derefs as needed.
There was no "single-layer codepath" to special-case
because the codepath operated on counts from the start.

I write this down because future-me might be tempted
to special-case again.
Single-layer feels easier
because it's what most cases use.
But the special case is what creates the gap.
The general case has no gap to create.

The probe pinned a worry
that turned out to be a feature of the bad architecture.
Fixing the architecture deleted the worry.
That's why we ran the probe.

## zero regressions

We touched the lift mechanism.
Every site that renders an expression goes through it.
I expected to spend the second half of the session
triaging tests that depended on old shapes.

We went from 425 / 19 to 412 / 33,
then 413 / 33,
then 433 / 13,
then 434 / 12.

The detour was real —
the first big landing introduced 22 regressions
that the Field-projection fix then closed.
But the regressions were all the same shape
(field access on a wrapper-typed thing),
and once the fix landed they all flipped at once.

No tactic broke because of changed name shapes.
No test depended on the specific `Tactus.Ref.mk t.deref` form
that we replaced with bare `t`.
The user-visible properties were unchanged;
the renderer just produced cleaner output for the same goals.

That's the test suite teaching us
the architecture was over-specified.
The omega + simp_all combinators were robust
to the structural changes
because they reason about the goal's meaning,
not its shape.

We didn't have to teach the tests anything.
The right answer was the answer they already accepted.
