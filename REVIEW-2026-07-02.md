## Tier 1 — soundness of the artifact chain

### 1.1 The emitted Lean environment is INCONSISTENT (inhabitedness) — top finding

Every vstd-using file emits axiom shapes like:

```lean
axiom seq.Seq : Type → Type
axiom seq.Seq.empty (A : Type) : seq.Seq A
axiom seq.Seq.index (A : Type) (self : seq.Seq A) (i : Int) : A
```

An axiom producing an `A` from arguments that exist for EVERY `A`
(empty seq + an Int) globally inhabits every type. Verified today —
this exact mirror derives `False` and closes an arbitrary wrong
postcondition (`/tmp/inconsistency_demo.lean`, ran clean):

```lean
theorem boom : False := (Seq.index Empty (Seq.empty Empty) 0).elim
theorem any_goal (x : Int) : x = x + 1 := boom.elim
```

`Tactus.index` (added today) shares the shape; so does any
value-returning uninterpreted spec-fn axiom whose result type is (or
contains, positively) a bare type param.

**Why Verus never had this problem:** SMT sorts are always non-empty —
the same axioms are sound in Z3's semantics. Lean types can be empty.
This is purely an encoding-boundary gap, and it's currently papered
over by convention ("Verus only instantiates at inhabited types") that
the Lean side does not enforce.

**Honest severity:** not reachable by accident — the tactus_auto
ladder will never construct `Seq.empty Empty`; every green result we
have is almost certainly genuinely green. But user tactic bodies are
free-form Lean, so "everything in the artifact chain is checked" is
currently backed by tactic goodwill, not by the kernel. That matters
for the trust story, and it matters SPECIFICALLY for the
proof-factory-game end goal, where proofs are adversarial user input.

**Remedy direction (uses machinery we already have):** `nonempty.rs`
already computes Nonempty-needs dataflow for `choose` and threads
`[Nonempty T]` brackets through binders and instances. Extend the same
need-computation to: any emitted axiom / uninterpreted spec fn whose
RESULT type contains a bare type param. User datatypes already emit
`deriving Inhabited`, and Lean synthesizes `Nonempty` for concrete
types, so the brackets should discharge everywhere legitimate code
instantiates. Verus-side guarantees make the bracket always satisfiable
in honest use; the kernel then enforces what convention used to.

### 1.2 Exec-mode instance methods bodied as `default` — needs a written soundness argument

`trait_emit.rs` (`Mode::Exec, Some(_)` arm): exec trait-method impls
render as `default` placeholders in instances. That plants a
DEFINITIONAL fact in the environment — `Class.method inst = fun … =>
default` — while call sites separately consume contract facts about
the same method (and cross-crate exec ensures are axiomatized). If any
emitted axiom ever states `P(Class.method …)` where `P` is false of
`default`, the two combine to `False` — same genus as 1.1, one more
step removed. I could NOT verify an actual derivation today (the
vec-clone axiom that looked closest is a trigger-carrier triviality),
so this is an unproven concern: either write the argument for why no
axiom can ever mention an exec method applied (and pin it with a
comment at the arm), or make the placeholder non-definitional (an
opaque constant per instance method, or an axiom-typed field).

### 1.3 The sanity checker's dotted-name bypass swallowed the entire cluster

`sanity.rs` allowlists bare names and lets every DOTTED identifier
pass ("dotted so it bypasses the sanity allowlist" is even the
documented idiom for slipping heads past it). Consequence, verified by
today's history: `Tactus.index` (undefined for months),
`view.DeepView.V T` (nonexistent constant), `.istuple%2`
(unsanitized `%` and all) — every one sailed through sanity and
surfaced only as Lean elaboration errors inside preambles, where they
poisoned whole files. The checker's value proposition erodes when the
escape hatch is that wide. Suggestion: sanity already caches prelude
names; extend to check dotted HEADS against (prelude names ∪ names of
commands emitted in the same stream), keeping a narrow escape list for
genuine Lean/Mathlib externals. Field projections (`.isFoo`, `.val0`)
would need either variant-accessor tracking or exclusion — even
heads-only would have caught three of today's six.

### 1.4 Flag-decides rests on two independent gates agreeing

The FileLoader's textual gate (`file_loader::is_lean_routed_exec_fn`,
tree-sitter) and the HIR gate
(`fn_call_to_vir::enclosing_fn_has_lean_tactic_blocks`) must classify
every fn identically; they parse different representations. Divergence
is fail-safe in direction (lex errors, or sanitized-away Verus code →
missing facts → verification failure, never silent wrongness), but the
failure reads as gibberish to a user. Cheap containment: a property
test that, for the e2e corpus, asserts sanitized-range set == the set
of spans the HIR side synthesizes TactusSpans for. Also note the
textual gate depends on tree-sitter-tactus tracking Verus's fn-mode
keyword set — a new mode keyword would misclassify (loudly).

## Tier 2 — architecture

### 2.1 Graduate `TypedExpr` from "opportunistic" to the renderer's return type

Today's bug 5 (tuple slot decorations vs stripped claimed typs) is the
latest member of the single most expensive bug family in the project's
history: U2, B1, #95, #144–146, Clusters A/B, the β refactor — all
wrapper-depth reconciliation at individual sites. The root is
structural: renderers produce UNTYPED `LExpr` and every projection /
call / binding site re-derives "what Lean type does this rendered
thing actually have" from SST claimed typs plus side channels
(binder_typs, fn_map, wrap counts). Each fix restores the implicit
invariant "rendered depth == claimed typ depth" at one more site.

REFACTORING2 §2.A closed the *context-locality* half and called
per-site TypedExpr adoption "opportunistic polish". Today is evidence
the remaining half still bites: making rendering return `(expr,
actual-lean-typ)` and bridging at COMPOSITION time (one coercion
site) would turn the invariant from per-site discipline into
structure. It's the biggest arc in this document and the only one I'd
call architectural debt rather than a bug: every future wrapper bug is
a session, and the family has never stopped producing.

### 2.2 Per-file preambles make every renderer bug a crate-wide outage

The whole cluster presented as "derived Clone fails" because one bad
item in the krate-wide broadcast union poisons EVERY file that carries
it. Structural posture today: each file re-contains the world, so
correctness of every file depends on the renderability of everything
any file needs. The mitigations already designed are the right ones —
promote them: defs-module as default (CRATEDEFS step 1) plus the
iterative-repair build (elaborate, drop erroring items by line
attribution, re-elaborate) as a firewall so the NEXT renderer bug
degrades one axiom instead of the crate. Post-cluster this is
prophylactic, which is exactly when it's cheap.

### 2.3 The two-renderer rule tax needs a stated discipline

Twin renderers are settled (rejected unification — don't re-litigate),
but today needed the same semantic fix applied twice for bug 6 (both
IsVariant arms) and three times for bug 3 (standalone, instance body,
proof-fn root). The unwritten rule that's actually in force: "a
semantic rendering rule lives in expr_shared or must be applied in
every arm that renders that construct." Write it into DESIGN and make
it a review checklist line; grep-level lint if it ever slips again.

### 2.4 `RenderCtx::empty()` inside instance-body rendering

`trait_emit.rs` renders instance member bodies with
`RenderCtx::empty()` — no fn_map, so the call-arg coercion bridge is
dark inside instance bodies. That's the same latent family as
everything above (a generic call inside an instance body whose arg
needs a wrapper bridge will render wrong). The ledger already tracks
empty() upgrades one at a time; after today, this specific site is the
one I'd do first.

## Tier 3 — smaller, concrete

* **[FOUND BY OWNER, FIXED same day] impl-block methods never received
  file-level imports** — the macro-expansion attachment loop
  (`syntax.rs` ~4812) visited only top-level `Item::Fn`, so impl/trait
  methods carried no `lean_import` attrs; krate_preamble's per-file
  import UNION is empty when methods are the only carriers. The
  `tactic_by || tactus_auto` gate had ALSO gone stale under
  flag-decides (attr-less exec fns got nothing). Now: exec-mode fns
  qualify unconditionally and impl/trait items are walked. Pinned by
  `test_impl_method_gets_file_level_import` (a crate with no top-level
  fns at all).

* **`--emit-lean` reports "N verified"** while skipping every Lean
  run (the note line says "Lean run skipped" but the summary still
  counts "verified"). Repeatedly confusing today even for me. Say
  "N emitted (not checked)" in the results line. Small,
  transparency-aligned.
* **`push_lenient` skips go to raw `eprintln`,** not the diagnostic
  reporter — a dropped broadcast axiom is invisible in normal output
  and manifests as distant proof failures. Route through the reporter
  as a note.
* **tactus_auto ladder corner:** an exec fn whose goal is trivial in a
  context with broadcast haves fails — every rung "fails" (`simp_all`
  errors with "no progress" rather than succeeding-as-no-op). Repro:
  `fn main() {}` in a crate with `broadcast use` (observed 2026-07-02).
  A terminal `trivial`-ish rung or `simp_all`-wrapped-in-`try` +
  `done` semantics fixes it.
* **Tactic proof fns don't receive broadcast haves** — exec obligations
  get `have _tactus_bc_i := …` injections; tactic-bodied proof fns
  don't, so a fact ambient in Z3-mode is unavailable in Lean-mode
  without naming the axiom (whose per-file emission isn't guaranteed
  either — it dep-walks only if referenced, chicken-and-egg). Decide
  the semantics deliberately (inject the same haves? require explicit
  reference but GUARANTEE emission of referenced axioms?) and document;
  right now it's an accident of the exec-path implementation.
* **Identifier hygiene:** `is_variant_node` built `is{variant}` by
  `format!` without `sanitize()` — that's how `%` reached emitted Lean
  (`istuple%2`). Tuple case is now unreachable, but audit the other
  `format!`-built identifier sites for the same skip (grep for
  `format!` feeding `field_proj`/`Var` constructions).
* **`Slice → List`, `Ptr → USize` renderings** (`to_lean_type.rs`)
  predate today's Vector work and have the same "erase what Lean can't
  say" smell the Array arm had. Nothing observed broken — but after
  the `[T; N]` experience, worth a deliberate pass over each Primitive
  mapping asking "what does vstd's spec surface for this type need the
  Lean type to carry?"

## What's healthy (kept deliberately short, but real)

The pin-everything discipline (every fix today has a load-bearing
test); the reject-and-record culture (REFACTORING2's do-not-re-litigate
list saved this review from re-arguing three settled designs); DESIGN/
HANDOFF as working memory (today's fixes leaned on 2026-05 archaeology
repeatedly); deterministic caching with spinoff isolation; the
transparency principles, which correctly predicted that the honest fix
(explicit spec-unfold proof blocks) would still be the right UX after
all six bugs were gone.
